memscope the 48-hour story · github

The more agents you run, the less Mac you're left with.

Agentic development scales sideways: every session spawns its own fleet of tool servers, connectors, and headless browsers. The sessions end. The fleets don't. By midweek the machine is sand, macOS starts force-quitting on its own judgment — and it doesn't kill politely. It kills the thread you were working in: the session holding three hours of context, the agent mid-migration, the reasoning you can't re-prompt.

$ ./memscope.sh guard --dry-run 41 orphaned agent-tool trees · parent: launchd · age: up to 3 days pinning ~4 GB of swap · invisible to Activity Monitor (named node) and every cleaner app → would reap all 41 · live sessions untouched
01 · THE PATTERN

You scale the workflow

More agents, more subagents, more tools. Whatever the framework — each session is really a process fleet: connectors, MCP servers, watchers, browsers. Fleet size × open sessions is your real footprint.

02 · THE DECAY

The machine turns to sand

Sessions end; children get orphaned and idle forever. RAM fills with finished work, swap grows to hold it, and every click pays a paging tax. It reads as "my Mac is old." It isn't.

03 · THE COST

Force-quit hell — lost threads

At the ceiling, macOS picks victims. The beachball is annoying; losing state is expensive — the long-running agent, the context you built all morning. That's the bill nobody itemizes.

There are two fixes for this. One costs a couple of thousand dollars. The other is a free shell script.

A 64 GB machine genuinely solves it — but a lot of that money buys headroom for processes that finished their work days ago. So run the script first. The dry-run is read-only and takes five seconds. If memscope finds nothing, buy the laptop with a clear conscience — at least you'll know the new RAM is going to live work, not ghosts. This page exists because that first pass found 4 GB of ghosts — and the upgrade stayed in the cart.

memscope: the census, then the guard

reap the provably dead
Tool trees whose session is gone — parented by launchd, older than 2h — are killed on sight. Nothing with a living parent is ever touched.
close the abandoned
A session with zero CPU for six straight hours is unread. Graceful TERM, notification, transcripts stay on disk — resume anytime, nothing lost.
warn before macOS picks victims
Under real pressure it names the actual consumers ("Chrome tabs 4.1G, Claude app 0.9G") while you can still choose what to close — instead of macOS choosing for you.
Safety contract: the kill-list is exactly two provable classes — dead fleets and 6h-zero-CPU sessions. Everything else is advice. Dry-run shows you every intended kill before you grant it anything.
