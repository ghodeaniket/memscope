memscope · for the Claude + Chrome + VS Code Mac

Everyone blames the 16 GB. A lot of it is already dead.

I’ve heard this from enough colleagues now. Claude Code, Chrome, VS Code, same MacBook. By midweek the machine is sand. Clicks beachball. macOS throws “out of application memory” and force-quits something they still needed. Then someone opens the Apple Store and starts pricing 64 GB.

The live apps are heavy. That’s real. But a chunk of the slowness isn’t Chrome or VS Code. It’s AI sessions they already closed.

$ ps -Axo pid,ppid,etime,args | grep mcp

Each Claude Code session spins up its own private fleet of MCP connectors. When the session dies, those children often don’t. launchd adopts them. They sit idle, named node in Activity Monitor, invisible to CleanMyMac, still pinning RAM and — the part nobody mentions — holding gigabytes of swap.

That’s why the Mac feels haunted after a week of agents. The work is gone. The processes aren’t.

memscope is the check, then the guard

One shell script. First it shows you the ghosts. Then, if you want, launchd runs it every two minutes:

— Reap the provably dead. Connector trees whose session is gone (parented by launchd, older than 2h) get killed. Nothing with a living parent is touched.
— Close the abandoned. A session with zero CPU for six straight hours is unread; it gets a graceful TERM. Transcripts stay on disk.
— Warn before macOS picks victims. Under real pressure it names the actual pigs (“Chrome tabs 4.1G, Claude app 0.9G”) while you can still choose.

The guard itself: 3.4 MB for 0.14 seconds, every two minutes, nothing resident in between. A memory tool that ran a fat daemon all day would be part of the problem.

On one 16 GB M4 running that exact stack, the first pass reaped 41 orphaned MCP trees. Swap 91% → 55% in minutes. Same workload the next day: no force-quit dialogs. The upgrade stayed in the cart.

See yours in five seconds

git clone https://github.com/ghodeaniket/memscope
cd memscope
./memscope.sh                # census: who is actually eating RAM
./memscope.sh guard --dry-run# what it would reap — trust nothing blindly
./memscope.sh install-guard  # the 2-minute launchd guard
./memscope.sh summary        # tonight: "ran 334 times · reaped …"

One file. Zero dependencies — ps, sysctl, awk. Read-only until you install the guard. The kill-list is two provable classes and nothing else. MIT.

If you run Claude Code next to Chrome and VS Code, you very likely have these orphans right now. It’s a known leak. Dry-run first.
